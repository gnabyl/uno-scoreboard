# Training

Fine-tunes a YOLO26 OBB model on the dataset generated by
`data/compose_hands.py`.

The labels are rotated boxes (`class x1 y1 x2 y2 x3 y3 x4 y4`), so the
checkpoint must be an **OBB** model (`yolo26n-obb.pt`). Detection weights like
`yolo26n.pt` or `yolov8n.pt` expect a different head and see no labels -
`train.py` checks this up front and stops with a readable error instead.

## Requirements

Use the project venv (has ultralytics + CUDA torch). Either activate it
from the repo root:

```powershell
.\.venv\Scripts\Activate.ps1
```

or call its Python directly:

```powershell
..\.venv\Scripts\python.exe train.py ...
```

## Generate data first

```powershell
cd ..\data
python compose_hands.py --count 10000 --val-frac 0.1 --warp 25
```

That gives 9,000 train / 1,000 val images, and val only uses background photos
the training images never saw. Add `--start-index 20000` to append another
10,000 to an existing dataset.

## Train

```powershell
cd ..\train
python train.py --export
```

| Flag | Default | Meaning |
|---|---|---|
| `--model` | `weights/yolo26n-obb.pt` | base weights (or a checkpoint to fine-tune); must be OBB |
| `--epochs` | 100 | epochs |
| `--imgsz` | 640 | input size |
| `--batch` | 16 | batch size (32 fits in 16 GB at 640) |
| `--workers` | 2 | DataLoader workers (raise it if the GPU waits on data) |
| `--patience` | 50 | early-stop after N epochs without mAP gain |
| `--device` | auto | `0`, `0,1`, or `cpu` |
| `--resume` | off | continue the newest OBB run from its `last.pt` |
| `--export` | off | export ONNX after training |

## From scratch vs fine-tune vs resume

- **From scratch** - `python train.py --model yolo26n-obb.yaml --epochs 200`
- **Fine-tune** on new data - `python train.py --model runs/uno_flip-X/weights/best.pt --epochs 50`
- **Resume** an interrupted run - `python train.py --resume`

`--resume` restores optimizer/epoch state and continues in the same run dir;
fine-tuning starts a fresh run initialized from the checkpoint weights.

## Output

Runs are written to `train/runs/uno_flip/` (auto-suffixed `-2`, `-3`, ...).
Each run contains:

- `weights/best.pt` - best checkpoint (use this)
- `weights/last.pt` - resumable checkpoint
- `weights/best.onnx` - ONNX export (when `--export`)
- `results.csv` / `results.png` - metrics per epoch
- `confusion_matrix.png`, `F1_curve.png`, `PR_curve.png`

## Model for the frontend

`--export` writes `weights/best.onnx` next to the checkpoint. Copy it over
(from the repo root):

```powershell
Copy-Item train\runs\uno_flip-X\weights\best.onnx app\public\model\uno-flip-detector.onnx -Force
```

The export deliberately uses `nms=False`: the graph emits raw rows
`(1, 300, 7)` = `cx, cy, w, h, conf, class, angle` (angle in radians, boxes in
640 px space). Ultralytics' built-in NMS is per-class, which is what produced
duplicate boxes when one card was read as different classes, so dedupe happens
in the app instead (`app/src/api-helper/localModel.ts`, rotated class-agnostic
IoU). After exporting, run one of the `test_images/` photos by hand to confirm
the app and the model agree.

## Inspect a run while training

`inspect_model.py` is a small Tk app for trying the current checkpoint on real
photos without stopping training:

```powershell
cd ..\train
..\.venv\Scripts\python.exe inspect_model.py
```

It loads `weights/best.pt` from the newest run under `runs/`, snapshots the
file before loading it, and by default reloads whenever it changes - so the
photo re-runs whenever a new best checkpoint is written. Inference runs on
**CPU by default** so it does not take the GPU away from training; pass
`--device 0` to use the GPU.

The left pane shows the annotated photo, the right pane lists each rotated box
with confidence, angle, and center/size in pixels. Use the **Weights** dropdown
to switch between `last`, `best`, and `auto`; `Save annotated...` writes the
full-resolution result. No class-agnostic dedupe is applied, so you see the
model's raw OBB output rather than the frontend's post-processing.

Each row has a **Box** toggle: click it (or select rows and press `Space`) to
hide that card's box and label. The **All** / **None** buttons show or hide
every box at once. `Save annotated...` saves exactly what is currently visible.

| Flag | Default | Meaning |
|---|---|---|
| `--run` | newest run | run directory or a specific `.pt` file |
| `--checkpoint` | `best` | `best`, `last`, or `auto` (last, else best) |
| `--conf` | `0.25` | starting confidence threshold (adjustable in the app) |
| `--imgsz` | `640` | inference size |
| `--device` | `cpu` | `cpu`, `0`, `0,1`, ... |
| `--interval` | `3` | seconds between checkpoint checks |
| `--image` | none | photo to open at startup |
| `--no-follow` | off | do not auto-reload changed checkpoints |

Examples:

```powershell
# Watch a specific run, on the GPU, starting with one of the test photos
..\.venv\Scripts\python.exe inspect_model.py --run runs/uno_flip-3 --device 0 --image ..\test_images\testimage1.jpg

# Compare the latest checkpoint instead of best.pt
..\.venv\Scripts\python.exe inspect_model.py --run runs/uno_flip-3 --checkpoint last
```

Shortcuts: `Ctrl+O` open photo, `F5` reload checkpoint and rerun, `Ctrl+S` save
the annotated photo.

## Notes

- Mosaic and horizontal flip are pinned to `0` in `train.py` (`PINNED_AUGMENT`),
  with no flags to turn them on. Mosaic tiles four photos into one 640 px
  sample, so cards get sliced at the seams and labels are clipped to the tile;
  the generator already produces crowded, overlapping hands at varied sizes. A
  horizontal flip is not a real card either - every class here is a glyph, and
  mirroring turns a 6 into a fake 9. HSV, scale, and translation jitter stay on.
- `data.yaml` uses relative paths, so `train.py` chdirs into `data/` first.
- Windows: PyPI `torch` is CPU-only - install the CUDA build from
  `https://download.pytorch.org/whl/cu126`.
