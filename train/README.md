# Training

Fine-tunes a YOLOv8 model on the dataset generated by
`data/compose_hands.py`.

## Requirements

Use the project venv (has ultralytics + CUDA torch). Either activate it
from the repo root:

```powershell
.\.venv\Scripts\Activate.ps1
```

or call its Python directly:

```powershell
..\.venv\Scripts\python.exe train.py ...
```

## Generate data first

```powershell
cd ..\data
python compose_hands.py --count 8000 --full-card
python compose_hands.py --count 2000 --min-cards 1 --max-cards 1 --full-card --start-index 8000 --keep-existing
```

## Train

```powershell
cd ..\train
python train.py --epochs 100 --batch 16 --workers 2 --export
```

| Flag | Default | Meaning |
|---|---|---|
| `--model` | yolov8n.pt | base weights (or a checkpoint to fine-tune) |
| `--epochs` | 100 | epochs |
| `--imgsz` | 640 | input size |
| `--batch` | 16 | batch size |
| `--workers` | 4 | DataLoader workers (use 2 on Windows if you hit shared-memory errors) |
| `--patience` | 50 | early-stop after N epochs without mAP gain |
| `--resume` | off | continue from the latest `last.pt` in `train/runs/uno_flip*/` |
| `--export` | off | export ONNX after training |

## From scratch vs fine-tune vs resume

- **From scratch** - `python train.py --model yolov8n.pt --epochs 100`
- **Fine-tune** on new data - `python train.py --model runs/uno_flip-X/weights/best.pt --epochs 50`
- **Resume** an interrupted run - `python train.py --epochs 100 --resume`

`--resume` restores optimizer/epoch state and continues in the same run dir;
fine-tuning starts a fresh run initialized from the checkpoint weights.

## Output

Runs are written to `train/runs/uno_flip/` (auto-suffixed `-2`, `-3`, …).
Each run contains:

- `weights/best.pt` - best checkpoint (use this)
- `weights/last.pt` - resumable checkpoint
- `weights/best.onnx` - ONNX export (when `--export`)
- `results.csv` / `results.png` - metrics per epoch
- `confusion_matrix.png`, `F1_curve.png`, `PR_curve.png`

## Model for the frontend

The frontend loads `app/public/model/uno-flip-detector.onnx`. After
retraining, re-export (with NMS baked in) and copy it over (from the repo
root):

```powershell
.\.venv\Scripts\python.exe -c "from ultralytics import YOLO; YOLO('train/runs/uno_flip-X/weights/best.pt').export(format='onnx', nms=True, imgsz=640)"
Copy-Item train\runs\uno_flip-X\weights\best.onnx app\public\model\uno-flip-detector.onnx -Force
```

`nms=True` bakes NMS into the graph so the browser side stays simple
(output `(1, 300, 6)` = `x1,y1,x2,y2,conf,class` per row).

## Notes

- `data.yaml` uses relative paths, so `train.py` chdirs into `data/` first.
- Windows: PyPI `torch` is CPU-only - install the CUDA build from
  `https://download.pytorch.org/whl/cu126`.
